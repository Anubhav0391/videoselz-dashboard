# VideoSelz Dashboard

A full-stack shoppable video analytics dashboard built as a take-home assignment.

The application provides a REST API for recording video engagement events and a React dashboard for viewing aggregated video performance metrics.

## Features

- Video analytics dashboard with views, clicks, and add-to-cart metrics
- Frontend conversion-rate calculation
- REST API for recording engagement events
- Server-side pagination
- Videos with no engagement events are displayed with zero metrics
- Simulated traffic generation
- Optimistic UI updates after successful event creation
- Request validation and error handling
- Loading, empty, and error states
- Responsive dashboard
- Semantic and accessible UI
- CSS Modules for styling

## Architecture

The application is split into a React frontend, Express backend, and SQLite database.

```text
┌──────────────────────┐
│    React Frontend    │
│      + Vite          │
└──────────┬───────────┘
           │ REST / JSON
           ▼
┌──────────────────────┐
│   Express Backend    │
│                      │
│  Event API           │
│  Analytics API       │
│  Validation          │
└──────────┬───────────┘
           │
           ▼
┌──────────────────────┐
│   SQLite Database    │
│                      │
│ Products             │
│ Videos               │
│ Engagement Events    │
└──────────────────────┘
```

The frontend communicates with the backend using an API base URL configured through an environment variable.

## Database Design

The database contains three main tables.

### Products

Stores product information associated with videos.

```text
products
--------
id
name
price
created_at
```

### Videos

Each video belongs to a product.

```text
videos
------
id
product_id
video_url
title
```

### Engagement Events

Stores individual engagement events for videos.

```text
engagement_events
-----------------
id
video_id
event_type
timestamp
```

Supported event types:

```text
view
click
add_to_cart
```

### Relationships

```text
Product 1 ──── N Videos
                  │
                  │
                  N
                  │
           Engagement Events
```

Analytics counts are derived from engagement events rather than stored separately.

## API

### Create Engagement Event

`POST /api/events`

Creates an engagement event for an existing video.

#### Request

```json
{
  "videoId": 1,
  "eventType": "view"
}
```

Supported event types:

* `view`
* `click`
* `add_to_cart`

The event timestamp is generated by the database.

#### Success Response

`201 Created`

```json
{
  "id": 1,
  "videoId": 1,
  "eventType": "view",
  "timestamp": "2026-08-27 10:30:00"
}
```

#### Errors

* `400 Bad Request` — invalid request body or event type
* `404 Not Found` — referenced video does not exist
* `500 Internal Server Error` — unexpected server or database error

### Get Video Analytics

`GET /api/analytics/videos`

Returns aggregated metrics for videos.

#### Query Parameters

| Parameter | Default | Description               |
| --------- | ------- | ------------------------- |
| `page`    | `1`     | Page number               |
| `limit`   | `5`     | Number of videos per page |

Example:

```text
/api/analytics/videos?page=1&limit=10
```

The API validates pagination parameters and limits the maximum page size.

#### Success Response

```json
{
  "data": [
    {
      "videoId": 1,
      "title": "Summer Collection",
      "productName": "Running Shoes",
      "views": 120,
      "clicks": 34,
      "addToCarts": 8
    }
  ],
  "pagination": {
    "page": 1,
    "limit": 10,
    "total": 4,
  }
}
```

Videos without engagement events are included with zero metrics:

```json
{
  "views": 0,
  "clicks": 0,
  "addToCarts": 0
}
```

The analytics query uses a `LEFT JOIN` so that videos with no engagement events are not excluded.

## Conversion Rate

Conversion rate is calculated on the frontend as required by the assignment:

```text
Conversion Rate = Add To Carts / Views × 100
```

If a video has zero views, the dashboard displays:

```text
-
```

## Simulate Traffic

The dashboard includes a **Simulate Traffic** button for demonstrating event ingestion.

When clicked:

1. An available video is selected.
2. A valid event type is selected.
3. A `POST /api/events` request is sent.
4. After a successful response, the affected row is updated locally.
5. The conversion rate automatically reflects the updated metrics.

The dashboard does not refetch the entire analytics dataset after a successful simulated event.

## Pagination

Pagination is handled by the backend using the `page` and `limit` query parameters.

The frontend uses the pagination metadata returned by the API to control the Previous and Next buttons.

Only the requested page of videos is fetched rather than loading the entire dataset into the browser.

## Validation & Error Handling

The backend validates incoming requests before performing database operations.

### Event Validation

* `videoId` must be a positive integer
* `eventType` must be one of the supported event types
* The referenced video must exist
* Database queries use parameters rather than string interpolation

### Pagination Validation

* `page` must be a positive integer
* `limit` must be a positive integer
* `limit` cannot exceed the configured maximum

Unexpected database or server errors return generic error messages without exposing internal database details.

## Local Setup

### Prerequisites

* Node.js
* npm

Check your installation:

```bash
node -v
npm -v
```

### 1. Clone the Repository

```bash
git clone https://github.com/Anubhav0391/videoselz-dashboard.git
cd videoselz-dashboard
```

### 2. Install Dependencies

Install backend dependencies:

```bash
cd server
npm install
```

Install frontend dependencies:

```bash
cd ../client
npm install
```

### 3. Environment Configuration

The required environment files for both the backend and frontend are included in the repository.

They contain only non-sensitive local development configuration, so they are intentionally committed for easier setup.

The backend runs on:

```text
http://localhost:3000
```

The frontend uses the backend API through:

```text
VITE_API_BASE_URL=http://localhost:3000
```

No API keys, credentials, secrets, or other sensitive information are stored in these files.

### 4. Seed the Database

From the `server` directory:

```bash
npm run db:seed
```

The seed script creates the SQLite database and inserts sample products, videos, and engagement events, including a video with no engagement events.

### 5. Start the Backend

From the `server` directory:

```bash
npm run dev
```

### 6. Start the Frontend

Open another terminal and run:

```bash
cd client
npm run dev
```

The Vite development server will start on its default development port.

## Design Decisions

### SQLite + better-sqlite3

SQLite keeps the project lightweight while providing the relational database functionality required by the assignment. `better-sqlite3` provides a simple synchronous API suitable for this small application.

### Raw SQL

Raw SQL was used instead of an ORM because the project has a small schema and limited database operations. This also keeps the analytics aggregation query explicit and easy to review.

### SQL Aggregation

Views, clicks, and add-to-cart counts are calculated in the database using conditional aggregation. This avoids loading individual engagement events into the application and counting them in JavaScript.

### LEFT JOIN

The analytics query starts from the `videos` table and uses a `LEFT JOIN` with engagement events. This ensures that videos with no events are still included with zero metrics.

### Frontend Conversion Rate

Conversion rate is calculated in React because the assignment requires it to be calculated on the frontend.

### Local State

React's built-in state and effects are sufficient for the current application, so no global state-management library was introduced.

### CSS Modules

CSS Modules provide scoped component styling while keeping the project lightweight.
